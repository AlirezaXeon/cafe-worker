# Café Roshan (Worker & Management System)

سیستم مدیریت و سفارش‌گیر یکپارچه کافه روشن بر بستر **Cloudflare Workers**، دیتابیس **Cloudflare D1 (SQLite)**، فضای ذخیره‌سازی **Cloudflare KV**، و ربات مدیریت تلگرام.

---

## ۱. معماری کلی سیستم (Architecture)

- **Backend / Edge Runtime**: پیاده‌سازی شده با Cloudflare Workers (ماژول‌های استاندارد ES) جهت پاسخ‌دهی بلادرنگ با حداقل تاخیر در Edge.
- **Database (D1)**: پایگاه داده SQLite ابری برای نگهداری محصولات (`products`)، دسته‌بندی‌ها (`categories`)، تنظیمات سایت (`site_settings`) و سفارش‌ها (`orders`).
- **Object / Blob Storage (KV)**: ذخیره‌سازی تصاویر، کشینگ حافظه و منو، و وضعیت قفل نرخ ورود (Rate limit & Lockout).
- **Static Assets**: رابط کاربری عمومی مشتریان و پنل مدیریت ادمین در پوشه `public/` به صورت دارایی‌های ایستا سرو می‌شوند.
- **Telegram Bot**: اعلان آنی سفارش‌های ثبت‌شده به مدیران کافه و امکان تایید/رد دوطرفه، مدیریت منو و آپلود تصویر مستقیماً از تلگرام.

---

## ۲. پیش‌نیازها (Requirements)

- **Node.js**: نسخه `22` یا بالاتر (`node -v >= 22`).
- **Wrangler**: ابزار رسمی Cloudflare Workers (نسخه موجود در `devDependencies`).

## ۴. پیکربندی کلودفلر و متغیرهای محرمانه (Configuration & Secrets)

فایل `wrangler.jsonc` ساختار منابع ابری را مشخص می‌کند:
- دیتابیس D1 با بایندینگ `DB`
- فضای KV با بایندینگ `PRODUCTS_KV`
- دارایی‌های استاتیک با بایندینگ `ASSETS`

### متغیرهای محرمانه (Secrets)
برای محیط پروداکشن، این متغیرها را با دستور `wrangler secret put <NAME>` تنظیم کنید:

| نام متغیر | نوع | توضیحات |
| :--- | :--- | :--- |
| `JWT_SECRET` | Secret | کلید محرمانه برای امضا و اعتبارسنجی توکن‌های ادمین (HMAC-SHA256). |
| `ADMIN_PASSWORD` | Secret | رمز عبور ورود به پنل مدیریت وب. |
| `TOKEN_VERSION` | Variable/Secret | نسخه توکن‌های ادمین (پیش‌فرض `"1"`). در صورت نیاز به باطل‌سازی تمام نشست‌ها مقدار آن افزایش می‌یابد. |
| `TELEGRAM_BOT_TOKEN` | Secret | توکن ربات تلگرام کافه دریافتی از BotFather. |
| `ADMIN_IDS` | Secret / Var | لیست آیدی‌های عددی تلگرام مدیران (جداشده با کاما، مثلاً `1234567,8901234`). |
| `WEBHOOK_SECRET` | Secret | رشته تصادفی و امن برای اعتبارسنجی وب‌هوک‌های دریافتی از تلگرام. |

## ۵. مایگریشن‌های پایگاه داده (D1 Migrations)

مایگریشن‌ها در پوشه `migrations/` نگهداری می‌شوند:
- `0001_init.sql`: جداول پایه دسته‌بندی‌ها و محصولات
- `0002_add_original_price.sql`: پشتیبانی از تخفیف و قیمت اولیه
- `0003_clear_dead_image_paths.sql`: پاکسازی مسیرهای منقضی تصویر
- `0004_add_available_column.sql`: فیلد موجود/ناموجود بودن محصول
- `0005_add_orders_table.sql`: جدول ثبت سفارش‌ها
- `0006_orders_hardening.sql`: فیلدهای ضدتکرار، هش آی‌پی و پیام‌های تلگرام
- `0007_site_settings.sql`: جدول تنظیمات سایت برای ذخیره لوگو، تصویر کاور و تعداد میزها (`logo`, `cover`, `tableCount`)
- `0008_orders_summary_index.sql`: ایندکس ترکیبی برای خلاصه‌سازی سفارش‌های در انتظار
- `0009_orders_table_pending_index.sql`: ایندکس بهینه‌سازی بررسی سقف سفارش در انتظار هر میز

### اعمال مایگریشن‌ها بر روی سرور Cloudflare D1:
```bash
npm run db:migrate:remote
```

## ۶. تنظیم وب‌هوک ربات تلگرام (Telegram Webhook Setup)

پس از دیپلوی ورکر، آدرس وب‌هوک تلگرام (`/tg-webhook`) را به همراه سکرت توکن ست کنید:

```bash
curl -F "url=https://your-domain.workers.dev/tg-webhook" \
     -F "secret_token=YOUR_WEBHOOK_SECRET" \
     https://api.telegram.org/bot<YOUR_TELEGRAM_BOT_TOKEN>/setWebhook
```
*(مقدار `secret_token` باید دقیقاً با مقدار secret متغیر `WEBHOOK_SECRET` همخوانی داشته باشد).*

## ۷. تدابیر امنیتی و پایداری (Security & Hardening)

- **اعتبارسنجی فایل‌های آپلودی**: بررسی بایت‌های جادویی (Magic bytes) برای فرمت‌های JPEG، PNG و WebP جهت جلوگیری از آپلود بدافزار یا فایل‌های متنی با پسوند جعلی.
- **مقاومت در برابر حملات زمان‌بندی (Timing-Safe Compare)**: استفاده از مقایسه با زمان ثابت در بررسی رمز عبور، سکرت وب‌هوک و توکن‌ها.
- **محدودیت نرخ و قفل حساب ادمین**: قفل تدریجی آی‌پی و محدودسازی پس از ۱۵ تلاش ناموفق برای ورود.
- **کنترل نرخ سفارشات و هانی‌پات**: محدودیت ۵ سفارش در هر ۱۰ دقیقه برای هر آی‌پی (با ذخیره هش امن SHA-256 و بدون ذخیره آی‌پی خام)، و محدودیت ۳ سفارش در انتظار برای هر میز.
- **جلوگیری از سفارش تکراری (Idempotency)**: پشتیبانی از کلید یکتا برای هر سفارش جهت مقابله با ارسال مجدد در صورت قطع و وصل شبکه مشتری.
- **تایید دوطرفه سفارش (Two-Way Sync)**: هماهنگی کامل تغییر وضعیت سفارش‌ها بین تلگرام و پنل وب همراه با بروزرسانی پیام‌های ثبت‌شده در کانال‌های ادمین.
- **محاسبات فروش بر مبنای افق زمانی تهران**: محاسبه دقیق آمار فروش امروز/هفته/ماه با در نظر گرفتن مبدا شنبه و منطقه زمانی رسمی ایران (`+03:30`).

## ۹. محدودیت‌های شناخته‌شده (Known Limitations)

- **عدم کارکرد Cache API روی `*.workers.dev`**: در سرویس Cloudflare Workers، رابط `caches.default` (کش لبه) روی دامنه‌های رایگان `*.workers.dev` غیرفعال است و پاسخ‌ها کش نمی‌شوند. به همین دلیل هر بار درخواست تصویر به یک خواندن از KV (KV Read) تبدیل می‌شود که سهمیه پلن رایگان را مصرف می‌کند. برای حل این مشکل، اتصال **دامنه اختصاصی (Custom Domain)** یا استفاده از **Cloudflare R2** برای ذخیره‌سازی تصاویر پیشنهاد می‌شود.
